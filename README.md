# 맥락 기반 게임 텍스트 번역

## 1. 컨셉 아이디어

### 1.1 배경: 기존 입력 방식의 한계 (AS-IS)
현재의 게임 텍스트 입력 방식은 **'단순 텍스트(Plain Text)'** 입력에 의존하고 있다.
* **방식:** 기획자가 *"전사 알렉스가 파멸의 검을 휘둘렀다."*라고 문장 전체를 문자열로 입력.
* **문제점:** AI 번역기는 텍스트만 보고 '파멸의 검'이 고유명사 아이템인지, 일반 명사인지 구분하지 못함. 이로 인해 용어 불일치와 치명적인 오번역(Hallucination)이 발생함.

### 1.2 혁신: 구조화된 태깅 시스템 도입 (TO-BE)
우리는 이번 프로젝트를 통해 **'ID 태깅(Tagging)' 시스템을 도입**한다.
* **개념:** 텍스트 내의 주요 고유명사를 텍스트가 아닌 **'불변의 ID 객체({ITEM_99})'**로 치환하여 저장한다.
* **효과:** 언어가 바뀌어도 ID는 변하지 않으므로, 데이터 무결성과 번역 일관성을 100% 보장한다.

### 1.3 해결 과제: 입력 비용의 최소화 (Smart Automation)
태깅 시스템은 번역 품질을 보장하지만, 기획자가 글을 쓸 때마다 `{NPC_05}` 같은 코드를 직접 찾아 입력해야 한다면 작업 효율이 급격히 떨어진다.
따라서 우리는 **'스마트 에디터(Smart Editor)'**를 통해 이 과정을 자동화하여, **"새로운 시스템을 도입하지만, 작업자의 입력 경험은 기존과 동일하게 유지"**하는 것을 목표로 한다.

### 1.4 인프라: Git 기반 형상 관리 (Version Control)
입력 툴의 백엔드 저장소를 일반 DB가 아닌 **Git**으로 구성한다.
* **목적:** 텍스트 데이터의 시계열적 변화 관리 및 버전 추적.
* **Branch Strategy:** 서비스 상황(이벤트, 업데이트 등)에 따라 동일한 ID의 텍스트가 달라져야 할 경우, **브랜치(Branch)**를 생성하여 대응한다. 이를 통해 원본 데이터를 훼손하지 않고 특정 시점의 텍스트를 안전하게 관리한다.

## 2. 시스템 워크플로우 (Workflow)

### 2.1 지능형 입력 프로세스 (Smart Data Entry)
기획자는 복잡한 ID를 알 필요가 없다. 시스템이 백그라운드에서 텍스트를 데이터로 변환한다.

1.  **자연어 입력:** 기획자가 에디터에 한글로 *"전사 알렉스가 파멸의 검을 찾고 있다."*라고 입력한다.
2.  **실시간 감지 및 자동 태깅 (Auto-Tagging):**
    * 에디터는 입력된 문장에서 DB에 등록된 키워드('전사 알렉스', '파멸의 검')를 감지한다.
    * 사용자의 엔터(Enter) 입력 시점에, 해당 단어들을 내부적으로 **`{NPC_05}`**, **`{ITEM_99}`**로 자동 치환하여 저장한다.
    * *(사용자 화면에는 여전히 가독성을 위해 한글 원문이 하이라이트 되어 표시된다.)*
3.  **모호성 해결 (Disambiguation):**
    * 만약 '배'를 입력했는데 이것이 '선박(Ship)'인지 '과일(Pear)'인지 모호할 경우, 에디터는 팝업을 띄워 기획자가 문맥에 맞는 카테고리를 선택하게 한다.

### 2.2 스토리 입력 모드 (Storytelling Context Mode)
단순 텍스트 나열이 아닌, 씬(Scene) 단위의 메타 데이터를 입력받아 번역과 더빙 효율을 극대화한다.

1.  **씬(Scene) 정의:** 텍스트 입력 전, 해당 씬의 **상황**과 **등장인물의 페르소나**를 정의한다.
2.  **감정 및 지문 입력:** 대사별로 캐릭터의 표정, 기분(Emotion)을 입력한다.
3.  **동시 활용 출력물 생성:**
    * **To LLM:** 씬 설명과 캐릭터 성격이 포함된 프롬프트를 전송하여, 단순 직역이 아닌 **'연기톤(Tone & Manner)'이 반영된 번역** 수행.
    * **To Voice Actor:** 대사, 지문, 감정 상태가 정리된 **'영화 대본 스타일'**의 출력물을 제공하여 녹음 디렉팅 비용 절감.

### 2.3 번역 파이프라인 (Batch Translation Pipeline)
효율성을 위해 단일 문장이 아닌 **배치(Batch)** 단위로 번역을 수행한다.

1.  **동적 글로서리 생성 (On-Demand Glossary Construction):**
    * 번역 요청된 **여러 문장**에 포함된 모든 태그(Tag)를 수집한다.
    * 해당 태그들의 번역어 정보를 DB에서 조회하여, **이번 배치 요청에만 사용할 전용 글로서리(JSON)**를 자동 생성한다.
    * *별도의 엑셀 용어집 파일은 존재하지 않으며 관리할 필요도 없다. 용어집의 단점인 불일치와 관리비용 문제를 원천 방지한다. *
2.  **AI 번역 요청:**
    * AI에게는 **'문장 배열(Array)'**, **'동적 글로서리'**, 그리고 스토리 모드에서 입력된 **'컨텍스트 정보'**가 함께 전달된다.
    * AI는 글로서리를 참조하여 다수의 문장을 동시에 번역하며, 문맥의 일관성을 유지한다.

## 3. 데이터 구조 및 프롬프트 설계

### 3.1 요청 JSON 스키마 (Request Payload)
개발팀은 아래 구조를 참조하여, 사용자가 입력한 자연어에서 태그를 추출해 `global_glossary`를 **자동 생성**하는 로직을 구현해야 한다. `items` 배열을 통해 여러 문장을 한 번에 처리하는 구조임에 유의한다.

```json
{
  "system_instruction": "Translate each object in the 'items' array. IMPORTANT: You must strictly adhere to the 'micro_glossary'. Use 'context' info to determine the tone.",
  
  "request_payload": {
    "source_lang": "ko",
    "target_lang": "en",
    
    // [Change] Global Glossary 제거됨.
    // 각 문장은 독립적인 컨텍스트를 가지며 서로 간섭하지 않음.

    "items": [
      {
        "id": "SEQ_001",
        "category": "Quest_Description",
        "source_text": "전사 알렉스가 잃어버린 파멸의 검을 찾고 있다.", 
        "tag_text": "{NPC_05}가 잃어버린 {ITEM_99}를 찾고 있다.",
        
        // [Micro-Glossary] 이 문장에 사용된 태그(NPC_05, ITEM_99) 정보만 포함
        "micro_glossary": {
          "{NPC_05}": {
            "src": "전사 알렉스",
            "tgt": "Warrior Alex",
            "cat": "Character_Name"
          },
          "{ITEM_99}": {
            "src": "파멸의 검",
            "tgt": "Blade of Ruin",
            "cat": "Weapon_Name"
          }
        }
      }
    ]
  }
}
```

## 4. 팀별 R&R (Roles & Responsibilities)

### 4.1 개발팀 (Tool & Backend)

* **스마트 에디터 (Smart Editor) 개발:**
    * 텍스트 입력 시 DB 키워드 매칭 및 자동 치환(Text-to-Tag) 알고리즘 구현.
    * **핵심:** 사용자가 `{ID}`를 직접 타이핑하는 일이 없도록 UX를 설계해야 함.
    * **스토리 모드 UI:** 씬 설정, 감정/지문 입력 필드 및 대본 형태의 뷰어 구현.
* **Git 저장소 연동:**
    * 텍스트 데이터를 JSON 등으로 변환하여 Git에 커밋/푸시하는 로직 구현.
    * 브랜치 생성 및 스위칭 기능 개발.
* **번역 API 모듈:**
    * 문장 내 태그 파싱 -> DB 조회 -> `global_glossary` JSON 조립 -> LLM 전송으로 이어지는 자동화 파이프라인 구축.
    * API 비용 최적화를 위해 `items` 배열의 크기(Chunk Size)를 적절히 조절하는 로직 포함.
    * API 호출시 *temperature 값을 0 으로 주어서 같은 원문을 매번 다르게 번역하는 문제 방지* (대사는 예외)



### 4.2 기획/데이터팀

* **기준 데이터 관리:** 스마트 에디터가 올바르게 작동하기 위해, 캐릭터명, 아이템명 등의 고유명사는 생성 시 DB에 정확한 명칭과 카테고리로 선등록되어야 함.
* **시나리오 구조화:** 텍스트 작성 시 씬(Scene) 단위의 상황 설정과 캐릭터 페르소나 정의 작업 수행.
* **UX 검증:** 자동 태깅된 결과가 의도한 문맥(예: '밤'이 먹는 밤인지, 어두운 밤인지)과 일치하는지 확인.

## 5. 기대 효과 (Conclusion)

이 프로젝트는 **'입력은 편하게, 처리는 정교하게'**라는 철학을 구현한다.

1. **품질 혁신:** ID 태깅으로 고유명사 오번역률 0% 달성 및 맥락 기반(Context-aware) 번역 품질 확보.
2. **효율 혁신:** 배치 처리를 통해 API 호출 횟수를 줄이고 대량 번역 속도 향상. 성우 녹음용 대본 자동 생성으로 프로세스 단축.
3. **경험 유지:** 스마트 에디터를 통해 기획자는 기존처럼 한글로 글을 쓰기만 하면 됨. (입력 비용 증가 없음)
4. **관리 제로:** 별도의 용어집 파일 없이, DB와 시스템이 실시간으로 번역 사전을 생성하고 관리함.
5. **유연한 버전 관리:** Git 브랜치 전략을 통해 시즈널 이벤트나 업데이트에 따른 텍스트 변경을 안전하게 관리.
